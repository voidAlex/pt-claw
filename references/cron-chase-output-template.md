# Cron 追剧输出模板

Cron 追剧任务（每日 10:00）的输出格式规范。遵循用户偏好「只推必要信息，不推送进度百分比/做种数/汇总统计等废话」。

## 输出结构

```
## 📺 今日追剧报告 — YYYY-MM-DD

追踪 N 项（M 电影 + K 演员），发现 X 部新资源。

---

### 🎬 电影名 — 🆕 新电影！ / ✅ 已全收录 / ⚠️ 无可用资源
（每部电影一个 section）

### 👤 演员名 — 🆕 N 部新作（JF 缺） / ✅ 已全收录 / ⚠️ 无可用资源
（每位演员一个 section）

---

> 回复「下 + 编号」确认下载（如 `下 SSIS-491`），或「全下」推送全部。
```

## 追踪统计速览（多演员时附在报告末尾）

多位演员追剧时，末尾附加一个紧凑统计表：

```
## 📊 统计

| 演员 | 片库已有 | JF外新发现 | PT有种 |
|------|----------|-----------|--------|
| 演员A | N | N → N(验证后) | N ✅ |
| 演员B | N | 0 | — |
| 演员C | 0 | 0 | 0 |

> 📂 下载路径：分类 `9kg` → `/9kg/x64/javdb-top250`
> 🔒 本次未自动下载。回复「下 + 番号」确认推送。
```

此统计表在**多位演员**（≥3）时必附，**1-2 位演员**时可省略。

## 各部分格式

### 🆕 新电影

```
### 🎬 中文名（英文名）— 🆕 新电影！
> 📅 YYYY 上映 | 🎬 类型 | 📝 一句话简介
JF: ❌ 未收录 | 下载历史: ❌ 未下载 | PT: N 条结果（站点列表）
| # | 版本 | 站点 | 💾 | 📊 | 🏷️ |
|---|------|------|-----|-----|-----|
| ⭐1 | 画质+编码-压制组 | 站点 | X.XGB | N | 促销 |
📂 下载路径: /path（分类：XXX）
```

### 🆕 新作（成人）

**当结果 ≤4 部时，用逐部详细介绍格式：**

```
### 👤 演员名 — 🆕 N 部新作（JF 缺）
> JF 已有 N 部（番号范围），以下 N 部未收录。

**① CODE** — 日文标题
| 📡 站点 | 💾 X.XGB | 📊 N seeds | 🏷️ 4K/字幕等 |
**② CODE** — 日文标题
...
📂 /path（分类：9kg）
```

**当结果 ≥5 部时，用密集表格格式（节省上下文、可快速扫描）：**

```
### 👤 演员名 — 🆕 N 部新资源

| # | 番号 | 日期 | 站点 | 做种 | 大小 |
|---|------|------|------|------|------|
| 1 | **CODE** | YYYY-MM-DD | 站点 | N | X.X GB |
| 2 | **CODE** ⚠️ | YYYY-MM-DD | 站点 | N | X.X GB |

> ⚠️ CODE = 多人共演（演员1/演员2/…），非单人作品

| 番号 | 简介 |
|------|------|
| CODE | 一句话剧情概括 |
| CODE | 一句话剧情概括 |
```

密集格式要点：
- 主表格（序号/番号/日期/站点/做种/大小）置顶，一目了然
- 简介用独立表格放在主表格下方，按番号对齐
- 多人共演作品用 ⚠️ 标记并注释参演人员
- 结果按日期倒序排列（最新在上）
- 结尾附统一路径行：`📂 /9kg/x64/javdb-top250（分类：9kg）`

### ✅ 已全收录

```
### 👤 演员名 — ✅ 已全收录
JF 已有 **N 部**（番号范围），PT 搜索结果全部已在库。无新资源。
```

### ⚠️ 无可用资源

```
### 👤 演员名 — ⚠️ 无可用资源
- JF: **0 部**（完全未收录）
- PTTime / M-Team 成人区: **0 结果**
- Sukebei 公开源: N 部（番号列表）但**全部 0 做种** 💀
- 原因: 该演员属 XXX 厂牌，作品未进入主流 PT 站
```

## 关键规则

1. **三重去重**：JF → download_history → 展示。JF 是权威来源。
2. **排序**：匹配用户偏好（HEVC/4K 优先）→ 做种数 → 体积
3. **M-Team URL 不预存**：URL 含 `t=` 时间戳，几分钟过期。只展示站点+大小+做种，不展示具体 URL。
4. **下载路径**：从 `user-preferences.md` 读取分类映射。
5. **无新资源时 → 输出 `[SILENT]`（三个字符，不多说、不报告原因）**。「新资源」= 今日候选清单（未入库未下载）中**不在上一轮报告里**的番号（标 🆕）。昨报仍在待确认的番号不是「新资源」，**不逐日重复推送**——一旦全部候选都已在上一轮报告过（即使还有大量昨报待确认），本轮就是 `[SILENT]`。⚠️ 只有跑完**全链路验证**（金丝雀 → 片单抓取 → 非标准过滤 → download_history filter → JF 逐码 → 交叉对比昨报）且确认**无任何 🆕 番号**时才能 `[SILENT]`；搜索返回 0 条（错误汉字/容器故障）≠ 无新资源，必须先按 lessons 顺序排查（繁简异体字/罗马字名/逐码补搜）再下结论，否则就是回归事故（见 cron-chase-lessons.md「跨日防回归」）。

   **⚠️ `[SILENT]` 必须裸输出，禁止前面加「验证摘要」前缀（2026-08-28 格式漂移事故）**：08-27 报告在 `[SILENT]` 前附了「Pipeline complete. Final verification summary」段落（canary/片单/候选/差集各一行），08-28 追剧 cron 读到上一轮输出后**照抄了该格式**，同样在 `[SILENT]` 前附验证摘要——这违反用户 cron prompt 明文「无新资源 → 整个回复就三个字符：[SILENT]，不要多说一个字（不要报告原因）」和用户偏好「只推必要信息，不推送进度百分比/做种数/汇总统计等废话」。验证数字的留存通道是 `/tmp/jbcheck/<date>/` 的产物文件（jf_notfound.txt、backlog 差集、crosscheck 输出），**不是交付消息**；事后判读走 cron-chase-lessons.md「数据源健康三连验」，不靠报告里的摘要。铁律：无新资源轮次 = 裸 `[SILENT]`，即使上一轮报告带了摘要也禁止模仿。

   **⚠️ 漂移复发 + 机械自查闸门（2026-08-29）**：铁律写入次日，08-29 运行**仍然**在 `[SILENT]` 前附了英文验证摘要（`Full pipeline complete. Verdict:` + 中文逐项）——声明式禁令不足以阻止行为，长流水线（金丝雀→片单→过滤→JF→差集→crosscheck）跑完后「汇报成果」的惯性会覆盖刚读过的文档教训。对策：**定稿前机械自查，不靠自觉**——所有工具调用完成后、写最终回复前，先问「这条回复里有没有 `[SILENT]`？」有 → 删除 `[SILENT]` 以外的**所有**字符（前置摘要、后置说明、任何语言），整条回复只留 `[SILENT]`；没有 → 正常写报告。验证数字的留存通道是 `/tmp/jbcheck/<date>/` 产物文件（jf_notfound.txt、差集、crosscheck 输出）和思考过程，不是交付消息。写完后再通读一遍，确认回复里除 `[SILENT]` 外无任何可见字符再结束。
6. **禁止输出**：Cron 进度百分比、做种汇总统计、初始化检查信息、"文件不存在"、诊断报告。
7. **跨日重复资源要标注「昨报」**：每天先对比上一轮报告（`session_search` 或 `~/.hermes/cron/output/<job_id>/` 最新文件），今日新发现标 `🆕`，昨日已报仍未下载的标 `（昨报）`，避免用户误以为又是新片、重复决策。统计表加「今日新发现」列。（2026-08-09 首次使用）注意：昨报清单只在**有 🆕 触发报告时**顺带列出；若本轮无任何 🆕，整轮输出 `[SILENT]`（见规则 #5），昨报不单独推送。（2026-08-18 澄清）⚠️ **昨报清单必须从最近若干份「非 [SILENT] 的实质报告」取并集重建**：追剧常连续多日 `[SILENT]`（无新资源），而 `[SILENT]` 回复本身不含任何番号。若只对比「最新文件」（`~/.hermes/cron/output/<job_id>/` 最新一份，可能是 `[SILENT]`），会丢失全部积压昨报、把几十部旧资源误判成 🆕。正确做法：从该目录往回翻，取最近 1-2 份**有内容**的报告（含「待确认/新发现」番号表格的），把其中所有番号 union 成「已报告集合」，再与今日「未入库未下载」集合做**差集**求 🆕（差集为空 → `[SILENT]`）。已验证（2026-08-19）：08-17/08-18 连续 `[SILENT]`，需 union 08-15 + 08-16 两份实质报告重建 79 码积压，差集=0 才正确 `[SILENT]`。
